- 장시간 플레이에서 메모리가 조각나던 문제 수정 (오류와 UI 잔상의 원인)

프레임 110,198에서 보고하신 오류와, 상점/조합에서 스토리맵으로 돌아올 때
이전 화면이 남는 증상의 원인을 찾았습니다. 둘 다 같은 원인입니다.

== 어떻게 찾았는가 ==

재현을 세 번 시도했지만 실패했습니다 (총 41만 프레임).
그래서 재현 대신 측정했습니다.

1. 전환마다 뭔가 남는가?
   전환 523회 동안 힙 59MB -> 162MB, 할당 34,799 -> 392,205
   전환 1회당 +198.5KB, +689 할당. 완벽히 선형.
   256MB 힙이면 약 1,000회 전환에 고갈됩니다.

2. 누구 누수인가?
   게스트 malloc 439,356회 / free 444,456회
   1.27GB를 주고받으며 free 가 더 많습니다. 게임은 누수하지 않습니다.

3. 그럼 뭐가 늘어나는가?
   사용 중 메모리는 50MB 로 평평
   빈 블록 개수   9,174 -> 53,814 개로 폭증
   최대 빈 블록   1,052,688 -> 68,496 바이트로 붕괴

   빈 공간이 재사용할 수 없는 조각으로 부서진 것입니다.
   전형적인 단편화이고, 그 할당자는 제가 만든 것입니다.
   블록을 쪼개기만 하고 합친 적이 한 번도 없었습니다.

== 수정 ==

인접한 빈 블록을 합치도록 했습니다.
블록을 주소 순으로 엮어서, 해제할 때 뒤쪽 빈 블록들을 흡수하고
앞쪽 빈 블록에 흡수되게 했습니다. 흡수된 슬롯은 재사용합니다.

                  이전        수정 후
  힙 증가(전환76회)  +8,211KB    +466KB
  메타데이터          85,999      34,082
  빈 블록 개수        53,814       1,033
  최대 빈 블록        68,496B  2,052,240B

전환당 힙 증가가 108KB 에서 6KB 로 줄었고, 관리 데이터는 고치기 전보다
오히려 적어졌습니다.

== 왜 두 증상이 같이 설명되는가 ==

세션이 길어져 힙이 조각나면 큰 할당이 실패하기 시작합니다.
   화면을 끝까지 못 그림  -> 이전 UI 가 남음
   조회가 널을 돌려주는데 게임이 확인 없이 참조 -> 오류

== 오류 메시지도 개선했습니다 ==

다음에 문제가 생기면 함수 이름까지 나옵니다.

  guest memory fault 00000006 size 2
    pc=100ca75e (_Z10logicFieldv+0xe4a)
    r0=00000000 ... frame=110198 heap=...KB allocs=...

보내주신 주소로 실제 검증했습니다. 전에는 제가 디스어셈블러로 찾아야
했던 정보가 이제 화면에 바로 나옵니다.

== 검증 ==

할당자는 모든 것의 토대라 전부 돌렸습니다.

  스토리 맵 1,259프레임 전부 원본 ARM 과 동일
  고정 기준선 교차 세션 검사 통과 (주소가 달라져도 화면/세이브 동일)
  120프레임 + 세이브 60개 원본 ARM 과 동일
  이동 세션 동일
  할당자 스트레스 테스트 통과 (살아있는 포인터 140,037개 정상, 겹침 0)
  v535 세이브 이어받기 통과
