- 카메라가 캐릭터를 더 빨리 따라옵니다 (A안)

== 먼저, 원인 조사 결과 ==

커널이 범인인지 확인하는 비교를 돌렸습니다.
스토리 맵 1,259프레임을 커널 켠 빌드와 끈 빌드로 각각 그려 비교했고,
다른 프레임은 0개였습니다. 커널은 무고합니다.

이걸로 포팅이 제어하는 모든 것이 증거로 확인되었습니다.
    네이티브 커널   맵 1,259프레임 원본과 동일
    프레임 속도     75틱 + 60 바닥, 조절 없이 테스트 -> 증상 그대로
    입력 빈도       맵에서 0개/1개/3개 -> 이동 완전 동일
    가상 시계       틱당 10,005us, 오버슈트 0
    화면 표시       레터박스 + 정확한 역변환 터치
    캔버스 기하     바이너리에서 확인, 렌더=출력=400x240

즉 카메라가 캐릭터를 뒤따라오는 것은 원본 게임의 동작이고,
포팅은 그것을 정확히 재현하고 있었습니다.

== 그래서 이번 변경은 "수정"이 아니라 "의도적 변경"입니다 ==

게임의 moveMap() 을 해독했습니다. 카메라는 목표 지점을 향해
"경과 시간 / 속도값" 만큼의 픽셀을 움직입니다.

    blx 0x5a60        r0 = 경과시간 / 속도값
    cmp r3, r0        남은 거리가 r0보다 크면
    adds r3, r0, #0       r0 만큼만 이동
    strh r2, [r1, #4] 스크롤 갱신
    bl 0xe458         맵 경계로 클램프

이 r0(이번에 움직일 픽셀 수)을 2배로 늘렸습니다.

안전한 이유
    원본이 "남은 거리"로 상한을 그대로 걸어두므로 넘어갈 수 없습니다
    도착 판정과 맵 경계 클램프도 건드리지 않았습니다
    바꾼 것은 한 레지스터 값 하나뿐입니다

후킹 위치는 함수 이름에서 찾고, 그 자리의 명령 바이트 6개를 대조한
뒤에만 적용합니다. v470 / v535 / v601 모두 동일한 바이트임을 확인했고,
다르면 아무것도 하지 않습니다.

== 솔직하게 말씀드릴 점 ==

호스트에서 효과를 입증하지는 못했습니다.
프로브가 도달하는 맵이 좁은 실내라, 카메라가 맵 경계에 고정되어
있어서 속도를 올려도 주인공 위치가 거의 안 바뀌었습니다 (-1.7%).
보정이 동작하는 것 자체는 확인했습니다 (1,259프레임 중 93프레임 변화).

말씀하신 "서 있으면 중앙에 있다"는 카메라가 자유롭게 움직이는
넓은 맵이라는 뜻이므로, 거기서는 효과가 나와야 합니다.
체감이 부족하면 배율만 올리면 됩니다 (한 줄, 2 -> 3 또는 4).

동일하다"가 계속 증명됩니다.

    120프레임 + 세이브 60개가 원본 ARM 코드와 완전히 동일
    고정 기준선 교차 세션 검사 통과
    할당자 스트레스 테스트 통과
    스토리 맵 1,259프레임 원본과 동일
