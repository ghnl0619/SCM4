== 고친 버그 ==

세이브 저장이 에뮬레이션 스레드를 멈추던 문제
    30초마다 세이브 60개를 전부 읽고, 백업 파일을 쓰고, 키체인까지
    호출하는 일을 게임이 도는 스레드에서 하고 있었습니다.
    주기적으로 게임이 잠깐 멈추는 원인입니다.
    이제 파일 이름/크기/수정시각만으로 변경 여부를 먼저 확인하고,
    실제로 바뀐 경우에만 읽습니다. 느린 쓰기 작업은 별도 큐로 옮겼습니다.

printf 계열 처리가 스택에 64KB를 잡던 문제
    인터프리터 훅 안쪽 깊은 곳에서 실행되는데, iOS의 보조 스레드 스택은
    512KB입니다. 호스트(8MB 스택)에서는 드러나지 않고 기기에서만
    터질 수 있는 형태였습니다. 런타임 구조체로 옮겼습니다.

프레임마다 하던 불필요한 할당 두 가지
    타이머 콜백이 CPU 상태 버퍼를 매 프레임 malloc/free 하던 것
    화면 표시 때마다 오버레이 이름 문자열을 새로 만들던 것

터치 입력 경로의 심볼 조회
    터치 이벤트마다 5,249개 심볼 목록을 문자열 비교로 훑고 있었습니다.
    시작할 때 한 번만 찾도록 했습니다.

== 발열 제어 개선 ==

    기존: Serious(이미 뜨거움)에서 60fps -> 20fps
    변경: Fair(첫 경고)에서 40fps, Serious에서 20fps

    게스트 시계가 프레임에 묶여 있어 프레임을 줄이면 게임 속도도 줄어듭니다.
    일찍 조금 줄이면 Serious까지 가지 않는 경우가 많고, 갑자기 1/3 속도가
    되는 것보다 체감이 훨씬 낫습니다.

== 측정해서 확인한 것 (추측 아님) ==

    할당자 메타데이터는 23,944에서 멈춤
        1,000 / 4,000 / 12,000 프레임 모두 동일. 장시간 실행 누수 없음
    Java 객체는 10개뿐 - 선형 탐색은 문제가 아니므로 건드리지 않음
    호스트 호출 디스패치 최적화는 CPU 0.5% - 사실상 의미 없음
        비용은 거의 전부 게스트 ARM 코드 해석에 있습니다
