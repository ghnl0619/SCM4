Heap exhaustion fixed, and the duel board is 7.7x faster.

The crash at frame 32367 - "guest heap exhausted (268351200 bytes, 68195
allocations)" - was not a leak. Live memory sits flat at 48.5 MB for an entire
session; what grew was free space the allocator could no longer find.

Coalescing merges a freed block with its neighbours, which makes it bigger,
and the allocator then left it filed under the size class it was first put in.
A request scans size classes from its own size upwards, so a block parked in a
smaller class is invisible no matter how large it has become. An audit built
for this reported it 3559 times in one session, always the same shape: a
1.3 MB block sitting in the 16-to-31-byte class while every 32-byte request
extended the heap instead. Over a long session that is the whole 256 MB.

Blocks are now re-filed the moment their size changes, which a doubly-linked
free list makes cheap. Over 40000 frames of colosseum mode-switching the heap
stays at 52.1 MB and does not move; before the fix the same session reached
92.6 MB and kept climbing.

Separately, isMapObjectCoverMotionObject - 56% of everything a duel interprets
- now runs natively, along with the two functions it calls. The duel board had
never been profiled or gated, which is why this was missed: it costs 5,088,709
interpreted bytes a frame against the story map's 617,215, and it is the screen
behind the "빠른 듀얼 또는 무한의 탑 진행 시 발열" report.

Gates, all re-run after the allocator change because heap layout is an input to
the game and every earlier pass was taken on the old allocator:

  story map     1259 / 1259 frames identical to original ARM, 11.4x
  duel board     581 /  581 frames identical to original ARM,  7.7x
  release         120 + 300 frames identical, 60 saves identical, 4.45x
  save carryover v535 saves carried into v601, preserved and advanced

Still open: the overlapping UI with dead buttons after colosseum -> dungeon ->
story mode, and the settings screen's back button after scrolling. A mode-switch
probe is running against this build; nothing reproduced yet, and neither path is
covered by any gate, so no claim is made that this release fixes them.
