- 카메라 지연 실험: 초당 75틱 (발열 바닥 60으로 보호)

== 먼저, 직전 실험이 틀렸던 게 아니라 "성립하지 않았습니다" ==

지난번에 초당 100틱으로 올렸을 때 발열 제어가 1/2, 1/3로 떨어뜨렸습니다.
그 값이 50과 33입니다. 즉 이전의 60보다 더 낮았습니다.
카메라에게 이전보다 더 낮은 틱 속도를 준 셈이고, "여전히 안 맞는다"는
딱 그 예상대로입니다. 프레임 속도는 사실상 테스트된 적이 없습니다.
제가 "배제됨"이라고 쓴 것은 틀렸습니다.

== 가설 ==

카메라가 캐릭터 쪽으로 "남은 거리의 일정 비율"씩 따라오는 방식이라면
지연은 고정된 "틱 수"입니다. 게임은 초당 100틱을 기대하는데 60틱만
주면, 같은 지연이 실제 시간으로는 1.67배 길어집니다.
이게 정확히 "카메라가 늦게 따라옴" 입니다.

== 이번 빌드 ==

    보통        75틱/초   (이전 60)
    따뜻함      60틱/초   (이전에 문제없던 값이 바닥)
    뜨거움      40틱/초

100이 아니라 75인 이유는 25% 증가라 감당 가능성이 높고, 발열 단계를
비율이 아닌 "절대 바닥"으로 바꿔서 조절이 걸려도 60 밑으로는 절대
내려가지 않게 했기 때문입니다. 지난번 같은 퇴보는 일어나지 않습니다.

== 확인해 주실 것 ==

    1. 카메라 지연이 눈에 띄게 줄었습니까?
    2. 발열이 심해져서 느려지는 느낌이 있습니까?

1번이 "예"면 원인 확정입니다. 그러면 틱 하나를 더 싸게 만들어서
100까지 올리는 작업으로 넘어갑니다. 어디를 줄여야 하는지는 이미
측정해 두었습니다 (게임플레이의 _putPixel 16%, 폰트 12%, 이미지 11%).

1번이 "아니오"면 이 가설은 폐기하고 다른 곳을 봅니다.

진단 기록에 30초마다 실제 동작 속도가 남습니다.
    guest memory 51234 KB in 23944 allocations at frame 12000, 75 Hz of 100

== 이번에 만든 것 ==

스토리모드 맵까지 들어가는 프로브를 완성했습니다.
    타이틀 -> 속성 -> 덱 -> 로비 -> 튜토리얼 듀얼 -> 스토리 맵
맵 위에서 캐릭터, 따라오는 동료, 방향패드가 화면에 나오는 것을
확인했고, 방향패드를 눌러 실제로 걷고 배경이 스크롤되는 것도
측정했습니다. 이동이 검증 가능해진 것은 이번이 처음입니다.
